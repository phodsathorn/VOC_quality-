## 🚀 1. จุดเริ่มต้นของโปรเจค (The Starting Point)

**เป้าหมาย:** สร้างเครื่องวัดคุณภาพอากาศในห้องพ่นสีฝุ่น (Powder Coating Booth) ก่อนปล่อยสู่ภายนอก
- **ฟังก์ชันหลัก:** ตรวจจับฝุ่นสี (PM), ทินเนอร์ (VOC), ควัน (Smoke) และตรวจสอบสภาพแวดล้อม (อุณหภูมิ, ความชื้น, CO2)
- **เทคโนโลยี:** ใช้ **จมูกอิเล็กทรอนิกส์ (E-Nose Array)** ประกอบด้วยเซนเซอร์หลายตัว ทำงานร่วมกับ **Machine Learning (TinyML / TFLite Micro)** บนไมโครคอนโทรลเลอร์ (ESP32) เพื่อจำแนกประเภทมลพิษ
- **จุดเด่น:** ไม่ใช้เซนเซอร์สำเร็จรูปที่มี AI ในตัว (เช่น BME688) เพื่อแสดงผลงานการ Train Model และทำ ML Pipeline ด้วยตนเองทั้งหมดสำหรับโปรเจคจบ

## ⚠️ 2. ปัญหาที่พบ & 🛠️ แนวทางการแก้ไข (Problems & Resolutions)

### ปัญหาที่ 1: สเปคฮาร์ดแวร์ในฝัน vs ของที่มีอยู่จริง (Hardware Mismatch)
*   **ปัญหา:** เอกสารออกแบบดั้งเดิมอ้างอิงอุปกรณ์สเปคสูงที่ยังไม่ได้ซื้อ (ESP32-S31, SEN55, SCD41) แต่ปัจจุบันมีเพียง "ชุดทดลอง" (ESP32-WROOM-32U, PMS5003, CCS811, DHT22, MQ-2/3/135, MiCS-6814)
*   **การแก้ไข:** ตกลงแบ่งฮาร์ดแวร์เป็น 2 เฟสชัดเจน:
    *   **Phase 1 (Experimental Setup):** ใช้ชุดทดลองที่มีอยู่เพื่อทำ MVP (Minimum Viable Product), เก็บ Dataset, และพิสูจน์ระบบ OTA Model Update
    *   **Phase 2 (Production Setup):** สเปคเป้าหมายสำหรับติดตั้งในโรงงานจริง (ทนทานและแม่นยำกว่า)
    *   *(อัพเดทเอกสาร `complete_project_reference.md` ให้แบ่ง 2 ชุดนี้ชัดเจนแล้ว)*

### ปัญหาที่ 2: ข้อจำกัดของ ESP32-WROOM-32U (ADC2 vs WiFi Conflict)
*   **ปัญหา:** ชิป ESP32 รุ่นคลาสสิก ไม่สามารถใช้ขา Analog แกนที่ 2 (ADC2) ได้เมื่อมีการเปิดใช้งาน WiFi ซึ่งโปรเจคนี้ต้องส่งข้อมูลผ่าน WiFi ตลอดเวลา
*   **การแก้ไข:** จัดสรร Pinout ใหม่ทั้งหมดใน `wiring_design.md` โดยย้ายเซนเซอร์ Analog ทุกตัว (MQ ทั้ง 3 ตัว และ MiCS-6814 ทั้ง 3 ขา) ไปกระจุกรวมกันที่กลุ่มขา **ADC1 (Pin 32-39)** เท่านั้น เพื่อให้ทำงานพร้อม WiFi ได้

### ปัญหาที่ 3: ธรรมชาติของเซนเซอร์ก๊าซ (Burn-in & Warm-up)
*   **ปัญหา:** เซนเซอร์ตระกูล MQ และ MOX (CCS811, MiCS-6814) หากเปิดใช้ทันทีค่าจะแกว่งมั่วมาก ทำให้ ML จำแนกผิดพลาด
*   **การแก้ไข:** ต้องทำตาม Datasheet อย่างเคร่งครัด:
    *   **CCS811:** ต้อง Burn-in 48 ชม. (ครั้งแรก) และ Warm-up 20 นาที (ทุกครั้งที่เปิดเครื่อง)
    *   **MiCS-6814:** ต้อง Warm-up 120 นาที
    *   **MQ Series:** ต้อง Burn-in อย่างน้อย 24-48 ชม.
    *   *(สร้างเอกสาร `data_collection_plan.md` เพื่อวางแผนการเก็บข้อมูล 4 Phase โดยให้ความสำคัญกับ Baseline และ Burn-in)*

### ปัญหาที่ 4: การกินกระแสไฟของ Heater เซนเซอร์ (Power Supply)
*   **ปัญหา:** เซนเซอร์ MQ ใช้แผ่นความร้อน (Heater) ซึ่งกินกระแสไฟสูงมาก (~150mA ต่อตัว) หากดึงไฟจากขา 5V ของ ESP32 โดยตรงผ่าน USB อาจทำให้ไฟตก (Brownout) และ ESP32 รีสตาร์ทตัวเอง
*   **การแก้ไข:** ใช้แหล่งจ่ายไฟแยกต่างหาก เช่น แบตเตอรี่ 18650 ต่อผ่าน Buck Converter ปรับลดแรงดันเหลือ 5V จ่ายให้เซนเซอร์โดยตรง (สำหรับชุดทดลอง) และใช้โมดูล Hi-Link AC-DC (สำหรับชุดจริง)

### ปัญหาที่ 5: โมเดล ML ตายตัว ไม่ยืดหยุ่น (Static Model Limitation)
*   **ปัญหา:** หากเทรนโมเดลให้รู้จักทินเนอร์ยี่ห้อ A แล้วนำกล่องไปติดตั้งที่โรงงาน B ซึ่งใช้ทินเนอร์ยี่ห้อ B โมเดลอาจจะทายผิดหมด
*   **การแก้ไข:** ยกระดับโปรเจคเป็น **"Adaptive E-Nose Platform"**
    *   เปลี่ยนจากการฝังโมเดลถาวร เป็นระบบที่ **Retrain ได้**
    *   ทำงานร่วมกับเพื่อนที่ทำเว็บ (Web Platform)
    *   ESP32 ส่ง Raw Data ขึ้นเว็บ → ช่างหน้างานกด Label ข้อมูลบนเว็บ → เว็บ Train Model ใหม่ → เว็บส่งโมเดลใหม่ `.tflite` กลับมาให้ ESP32 ผ่าน **OTA (Over-The-Air) Update**
    *   *(สร้างเอกสาร `adaptive_enose_analysis.md` เพื่อวิเคราะห์ความเป็นไปได้ และงานวิจัย IEEE ที่รองรับ)*

### ปัญหาที่ 6: Sensor Drift (ค่ามาตรฐานไม่เท่ากันในแต่ละสภาพแวดล้อม)
*   **ปัญหา:** เซนเซอร์ตัวเดียวกันแต่อยู่คนละโรงงาน (อุณหภูมิ/ความชื้นต่างกัน) ค่าเริ่มต้น (Baseline) จะไม่เท่ากัน
*   **การแก้ไข:** แทนที่จะใช้ค่า Raw ADC ไปสอน ML ตรงๆ ให้ใช้ **Relative Calibration (Rs/Ro)** คือการนำค่าที่อ่านได้ไปหารด้วยค่า Baseline ของอากาศสะอาดในโรงงานนั้นๆ ก่อนส่งเข้า ML และต้องส่งค่า `scaler_params` (Mean/Std) ที่ได้จากการ Train แนบมาพร้อมกับ OTA Model ทุกครั้ง
